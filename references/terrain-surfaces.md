# TIN and raster terrain

Sources: QG-TIN, QG-CRS. Read [coordinate systems](coordinate-systems.md) when units or reprojection are involved.

- **[Safeguard]** Preserve original point IDs, XYZ values, and triangle connectivity. Validate duplicate IDs, nonfinite coordinates, nontriangular faces, missing point references, and ambiguous surface names. Retrangulating the point cloud can change the intended surface and breakline constraints.
- **[Math]** Within a nondegenerate triangle, interpolate elevation on its plane (equivalently by barycentric weights). Test vertex values and interior known-plane points. Reject or explicitly report zero-area triangles; the reviewed implementation skips degenerates, which must not become a silent global policy.
- **[Application; QG-TIN]** Raster cells sample the TIN at pixel centers. The reviewed grid snaps bounds to resolution, uses a north-up negative Y pixel step, and writes Float32 elevations with nodata outside populated triangles. Confirm pixel-center positions and geotransform, not just raster dimensions.
- **[Safeguard]** Resolution is in output horizontal units and controls representation, not measurement accuracy. Predict dimensions and allocation before rasterizing; the current optional cell limit defaults to no cap. Choose an operational limit for the actual task rather than assuming one exists.
- **[Safeguard]** Quantify Float32 elevation rounding at the dataset's elevation magnitudes. Preserve source precision separately when required. A valid elevation must not collide with the selected nodata value; verify outside coverage, overlaps, clipping, and any areas left unpopulated.
- **[Unknown/application]** Triangle boundary edges do not automatically identify engineering voids, interior holes, or breakline semantics. The reviewed code does not implement a complete hole/void model. Do not fill such regions or invent semantics from a closed boundary alone.
- **[Safeguard]** Keep horizontal transformations and vertical values independent. QGIS's XY reprojection preserves original Z, including an unknown vertical unit/datum. A target horizontal CRS in meters does not make Z meters. If vertical conversion is required, specify and validate it separately.
- **[Safeguard]** Validate output CRS, axis order, horizontal resolution, vertical interpretation, nodata, bounding box, and populated elevation range with GDAL or equivalent metadata inspection. Compare selected raster centers to the source triangles numerically; visual agreement over imagery only checks gross placement.
- **[Application regression/runtime evidence]** Synthetic fixtures and headless Processing tests exercise TIN/GeoTIFF output. Documented private OpenRoads runtime checks establish that particular exports were processed, not survey-control accuracy or all Civil 3D/OpenRoads surface semantics.
